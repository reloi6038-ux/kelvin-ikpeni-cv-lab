Privacy

Your resume is your business.

This page describes exactly what CV Lab stores, where it lives, how it is protected, and how to remove it. It is written to be read, not skimmed.

Last updated: 18 October 2026.

The short version

  • You can use CV Lab without an account. There is no email, password, or third-party login.
  • Drafts live in your browser. Saved resumes live on our server keyed to an anonymous session token.
  • We do not run analytics on your resume content, and we do not send resume data to any third party.
  • You can delete everything with one button on this page.

What CV Lab stores

In your browser (localStorage)

  • kilab.session — a 64-character random token. Generated by your browser. Grants access only to the resumes created with it.
  • kilab.activeResumeId — the currently-open resume id.
  • kilab.draft.<id> — your in-progress edits for a given resume.
  • kilab.theme — light or dark preference for the site's UI.
  • kilab.pendingTemplateId — a template you selected from the gallery, consumed by the builder on next load.

This data is stored by your browser on your device. It is not transmitted to CV Lab until you click Save in the builder.

On our server (MongoDB Atlas)

  • The resume itself: the name, title, contact details, summary, and section content you entered.
  • ownerHash — a keyed hash (HMAC-SHA256) of your session token. The token itself is never stored server-side.
  • Two timestamps: when the resume was created and last saved.
  • If you delete a resume, we record a deletedAt timestamp instead of erasing the row immediately. This lets us recover from accidental deletion and prevents the same record from being served again.

In our logs

  • HTTP request metadata (method, path, status, timing, IP address). No resume content.
  • Server error messages for failed requests. These may contain internal identifiers but never user-entered resume text.

How we protect it

  • The session token is unguessable. It is 64 hex characters (256 bits) generated by crypto.getRandomValues.
  • The token is hashed before storage. Even if the database were exposed, tokens alone could not be used to access anything.
  • Every resume request verifies ownership. Attempting to read or write another person's resume returns a plain 404 — indistinguishable from "not found" — so you cannot probe which ids exist.
  • Private responses disable caching. No CDN, browser cache, or reverse proxy caches your resume content.
  • Rate limits guard against brute-force scanning and abuse.
  • Security headers (Helmet) reduce the impact of client-side attacks.
  • No PII in logs. The server never logs your resume content.

How we do NOT use your data

  • We do not sell or share your resume with any third party.
  • We do not run analytics or advertising networks that receive your resume text.
  • We do not use your resume to train machine-learning models.
  • We do not require an account, email address, or phone number to use the service.

Honest limitations

  • No cross-device recovery. Your saved resumes are recoverable only from the same browser, because the session token is stored in that browser's localStorage. If you clear browser data or switch devices, the resumes on the server become inaccessible to you. Download your resume before clearing browser data if you need to keep it.
  • Browser storage can be cleared. Drafts in localStorage are lost when the browser's site data is cleared, in private browsing windows that close, or when storage pressure forces eviction.
  • Deletion is soft-then-purged. When you delete a resume, the server marks it deleted and it disappears from your list, but the underlying row remains until the operator purges it under a retention policy. You can request a full deletion using the button below; if you want your server copy purged immediately, that request is included in the deletion action.
  • Third-party image hosts. If you paste a profile photo URL, the browser fetches it from that host when the resume renders. The host may log your IP address. Choose hosts you trust.

Delete everything now

This button performs all three cleanup steps in one action:

  1. Server deletes every resume associated with this browser's session token.
  2. All local drafts, saved-resume ids, and preferences in localStorage are cleared.
  3. A fresh anonymous session token is generated for any future use of the site.

Downloaded resumes are not affected — anything you already saved as PDF or DOCX on your device is outside CV Lab's control.
